# jiaofu115

自托管的「BT 站点新片 → 磁力链 → 115 网盘离线下载」自动化工具。

定时抓取站点新上架的电影 / 电视剧 / 动漫，按评分和画质自动挑磁力推送到 115 离线下载。带网页界面，手机也能用。

---

## 功能

| 功能 | 说明 |
|---|---|
| 新片监控 | 定时抓取站点列表，带封面、评分、体积、磁力数量 |
| 自动推送 | 发现新条目自动选磁力、推送 115 离线下载 |
| 评分门槛 | 只推「评分 ≥ 设定值」的片子，门槛在设置里下拉选；豆瓣分优先，没有豆瓣分用 IMDB |
| 磁力挑选 | 优先 4K；同一画质里优先 115 能秒传的；可设体积区间、单轮 / 每日上限 |
| 订阅追片 | 填个片名就能盯；剧集选「追更」按集下载；磁力全是死种时自动改用站点 115 网盘分享 |
| 手动搜索 | 搜片名，一键把磁力或 115 网盘分享推到自己的网盘 |
| 洗版升级 | 发现更高画质时，删掉 115 上的旧文件换新的（进回收站，可还原） |
| 115 扫码登录 | 网页版 / 安卓 / iOS / 支付宝 / 微信 / TV / 鸿蒙，共 7 种扫码渠道 |
| 分栏目目录 | 电影、电视剧、动漫各自落到不同的 115 目录，不会混在一起 |
| 推送记录 | 每条离线任务的状态和失败原因 |

> 本版本只做「站点 → 115 离线」这一条链路，不含自动整理、媒体库刮削或第三方下载器的联动。下完之后怎么整理，交给自己的习惯或别的工具。

## 快速开始

镜像已经公开，**不需要登录 GitHub、不需要 `docker login`**，直接拉就能用。同时提供 `amd64`（x86 NAS / 迷你主机 / 群晖大部分机型）和 `arm64`（ARM NAS、树莓派、M 系列 Mac）两个架构，Docker 会自动挑对应的。

### 方式一：docker compose（推荐）

新建一个目录，放一个 `docker-compose.yml`：

```yaml
services:
  jiaofu115:
    image: ghcr.io/loading543/jiaofu115:latest
    container_name: jiaofu115
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
      - PORT=8123
      - DATA_DIR=/data
    ports:
      - "8123:8123"
    volumes:
      - ./data:/data
```

然后：

```bash
docker compose up -d
```

### 方式二：docker run

```bash
docker run -d \
  --name jiaofu115 \
  --restart unless-stopped \
  -p 8123:8123 \
  -e TZ=Asia/Shanghai \
  -v $(pwd)/data:/data \
  ghcr.io/loading543/jiaofu115:latest
```

### 打开

```
http://你的NAS的IP:8123
```

端口冲突就改映射的左边，比如 `-p 9000:8123`。

## 首次配置

一共三步，都在左侧菜单里。

### 1. 登录站点

左侧「站点登录」→ 填站点用户名和密码 → 登录。

站点有防爬验证和会话限流，程序内部已经处理，不用管。如果显示「需要验证码」，按提示点一下即可。

### 2. 扫码登录 115

左侧「115 账号」→ 选一种扫码方式 → 用手机扫码授权。

推荐「115 网页版」，用手机上的 115 App 扫。也支持支付宝、微信、TV 版、鸿蒙客户端。

### 3. 选保存目录

同一个页面往下拉，「推送保存目录」→「选择目录」→ 挑一个 115 里的目录，比如 `/影视/电影/离线`。

以后离线下载的文件就落在这里。不选则用 115 默认的「云下载」目录。设置页里还能给电影 / 电视剧 / 动漫各指定一个目录。

> 建议单独建一个 `离线` 目录存放，方便你后续自己整理。

到这里就跑通了。程序会按设定间隔（默认 15 分钟）抓列表、挑磁力、推送。

## 怎么用

### 最新更新

列出站点上所有条目，按上架时间倒序。每张卡片有封面、类型、评分、体积、磁力数。

- 顶部可以筛选电影 / 电视剧 / 动漫，也可以按体积或时间排序
- 点卡片进详情，能看到所有磁力链，手动选一条推 115
- 右上角「暂停推送」可以一键停掉自动推送（抓列表照常）

**首次运行会建立基线**：库里已有的条目都算历史，不会突然把整站推一遍。

### 评分门槛

「设置 → 评分门槛」里下拉选一个分数（不限 / 5.0 / 5.5 … 9.0）。自动推送只推达到门槛的片子，订阅和手动推送不受影响。

- 评分优先取豆瓣，没有豆瓣分才用 IMDB
- 刚上线的片子常常还没有分，默认「没分不推」，等出分后下一次同步会补进队列
- 想「没分也照推」，把「没评分的也推」勾上即可

### 搜索

输入片名 → 搜索 → 结果里点「磁力转」或「115 转」。

「磁力转」是把种子离线到 115；「115 转」是用站点的网盘分享做服务端复制，秒级完成。每条只走你选的那条路。

### 订阅追片

填片名（可选年份、画质、体积）就能加一条订阅，站点暂时没有也不影响，出了会自动推。

- **电影**：有源就推，出现更高画质自动洗版
- **电视剧 / 动漫**：选「追更」后每更新一集自动下一集，不用等完结；也可以选「等完结再推」
- 磁力全是死种没速度时，自动改用站点的 115 网盘分享转存（服务端复制，不占下载带宽）

### 洗版升级

扫描已经推送过的条目，如果站点上出现了画质更好的版本（分辨率更高 / 片源更好），会把 115 上的旧文件删掉换新的。

- 旧文件进 115 回收站，能还原，不是彻底删除
- 只在你手动点「开始扫描」时才跑，不自动执行
- 扫描结果会列出「旧 → 新」的对比，确认后才动手

### 设置

- **自动推送开关**：总开关，关掉后只抓列表不推送
- **推送间隔**：多久抓一次
- **评分门槛**：低于设定分数的不推
- **体积限制**：小于多少 GB 或大于多少 GB 的不推
- **单轮 / 每日上限**：控制节奏，避免一口气推太多把 115 打爆
- **115 空间保护**：剩余空间低于设定值时自动停推
- **优先 4K / 优先秒传**：画质优先，同一画质里挑能秒传的
- **栏目开关**：电影 / 电视剧 / 动漫，可以单独关掉某一类
- **补推历史**：关掉后只推「今天以后新上架」的，不回补老片

### 推送记录

每条离线任务的提交状态。失败的会写明原因（磁力失效、115 空间不足、任务被拒等）。

## 数据与备份

所有运行时数据都在 `data/` 目录下的一个 SQLite 文件里：

```
data/app.db
```

**备份**：

```bash
tar czf jiaofu115-backup.tar.gz data/
```

**恢复**：把 `data/` 放回去，重启容器。

**升级**：

```bash
docker compose pull && docker compose up -d
```

数据库表结构会在启动时自动建，`data/` 不用重建。

## 自己构建镜像

不用等 CI，本地也能构建：

```bash
git clone https://github.com/Loading543/jiaofu115.git
cd jiaofu115
docker build -t jiaofu115 .
docker run -d --name jiaofu115 --restart unless-stopped \
  -p 8123:8123 -v $(pwd)/data:/data jiaofu115
```

仓库里带了 GitHub Actions 配置（`.github/workflows/docker.yml`），推到 `main` 会自动构建并推送到 `ghcr.io`，打 `v*` tag 会额外打版本标签。

## 常见问题

**Q：页面能打开，但列表一直空**

先看「站点登录」页的状态是不是已登录。没登录的话程序会跳过抓取（日志里只有一条提示，不会刷屏）。

**Q：115 提示未登录**

115 的 Cookie 有有效期，重新扫码即可。如果频繁掉线，可能是 115 风控，换个网络环境或隔一会儿再试。

**Q：推送一直失败**

看「推送记录」里的具体原因。常见的是磁力失效（站点那边的种子挂了）或 115 空间不足。

**Q：新片不少，但自动推送没动**

先看「设置 → 评分门槛」。刚上线的片子常常还没有评分，默认不推；把门槛调低或勾上「没评分的也推」就会进队列。

**Q：`docker pull` 卡住或特别慢**

`ghcr.io` 国内直连有时不稳。给 Docker 配一下镜像加速或代理即可。实在拉不动就 `git clone` 下来本地 `docker build`（见「自己构建镜像」一节），效果完全一样。

**Q：怎么完全卸载**

```bash
docker compose down
rm -rf data/
```

## 安全提醒

**这个程序没有登录密码。** 谁能访问 `8123` 端口，谁就能操作你的 115 网盘（删文件、离线下载）。

- **只在内网用，不要把端口映射到公网**
- 必须外网访问的话，前面挂 Nginx / Traefik，加一层 HTTP Basic Auth
- 仓库里不含任何账号、Cookie 或内网地址；你自己的凭据只存在本地 `data/app.db`，**别把这个目录分享出去**
- `.gitignore` 已经排掉了 `data/` 和 `.env`，但自己提交前再看一眼
