# jiaofu115

自托管的「BT 站点新片 → 磁力链 → 115 网盘离线下载」自动化工具。

定时抓取站点新上架的电影 / 电视剧 / 动漫，自动挑体积最大的磁力链推送到 115 离线下载。带网页界面，手机也能用。

---

## 功能

| 功能 | 说明 |
|---|---|
| 新片监控 | 定时抓取站点列表，带封面、体积、磁力数量 |
| 自动推送 | 发现新条目自动选磁力、推送 115 离线下载 |
| 磁力挑选 | 默认按体积最大挑；可设体积区间、单轮推送上限 |
| 手动搜索 | 搜片名，一键把磁力推到 115 |
| 洗版升级 | 发现更好画质时，删掉 115 上的旧文件换新的（进回收站，可还原） |
| 115 扫码登录 | 网页版 / 安卓 / iOS / 支付宝 / 微信 / TV / 鸿蒙，共 7 种扫码渠道 |
| 推送记录 | 每条离线任务的状态和失败原因 |

> 本版本不含 MoviePilot 自动整理功能，只做「推送 115」这一条链路。

## 快速开始

### 方式一：docker compose（推荐）

新建一个目录，放一个 `docker-compose.yml`：

```yaml
services:
  jiaofu115:
    image: ghcr.io/loading543/jiaofu115:latest
    container_name: jiaofu115
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
      - PORT=8123
      - DATA_DIR=/data
    ports:
      - "8123:8123"
    volumes:
      - ./data:/data
```

然后：

```bash
docker compose up -d
```

### 方式二：docker run

```bash
docker run -d \
  --name jiaofu115 \
  --restart unless-stopped \
  -p 8123:8123 \
  -e TZ=Asia/Shanghai \
  -v $(pwd)/data:/data \
  ghcr.io/loading543/jiaofu115:latest
```

### 打开

```
http://你的NAS的IP:8123
```

端口冲突就改映射的左边，比如 `-p 9000:8123`。

## 首次配置

一共三步，都在左侧菜单里。

### 1. 登录站点

左侧「站点登录」→ 填站点用户名和密码 → 登录。

站点有防爬验证和会话限流，程序内部已经处理，不用管。如果显示「需要验证码」，按提示点一下即可。

### 2. 扫码登录 115

左侧「115 账号」→ 选一种扫码方式 → 用手机扫码授权。

推荐「115 网页版」，用手机上的 115 App 扫。也支持支付宝、微信、TV 版、鸿蒙客户端。

### 3. 选保存目录

同一个页面往下拉，「推送保存目录」→「选择目录」→ 挑一个 115 里的目录，比如 `/影视/电影/离线`。

以后离线下载的文件就落在这里。不选则用 115 默认的「云下载」目录。

> 建议单独建一个 `离线` 目录存放，方便你后续自己用别的方式整理。

到这里就跑通了。程序会按设定间隔（默认 15 分钟）抓列表、挑磁力、推送。

## 怎么用

### 最新更新

列出站点上所有条目，按上架时间倒序。每张卡片有封面、类型、体积、磁力数。

- 顶部可以筛选电影 / 电视剧 / 动漫，也可以按体积或时间排序
- 点卡片进详情，能看到所有磁力链，手动选一条推 115
- 右上角「暂停推送」可以一键停掉自动推送（抓列表照常）

**首次运行会建立基线**：库里已有的条目都算历史，不会突然把整站推一遍。

### 搜索

输入片名 → 搜索 → 结果里点「秒传 115」。

默认按体积最大挑磁力，也可以在结果里展开挑别的版本。

### 洗版升级

扫描已经推送过的条目，如果站点上出现了画质更好的版本（分辨率更高 / 片源更好），会把 115 上的旧文件删掉换新的。

- 旧文件进 115 回收站，能还原，不是彻底删除
- 只在你手动点「开始扫描」时才跑，不自动执行
- 扫描结果会列出「旧 → 新」的对比，确认后才动手

### 设置

- **自动推送开关**：总开关，关掉后只抓列表不推送
- **推送间隔**：多久抓一次
- **栏目开关**：电影 / 电视剧 / 动漫，可以单独关掉某一类
- **体积限制**：小于多少 GB 或大于多少 GB 的不推
- **单轮上限**：一次最多推几条，避免一口气推太多
- **补推历史**：关掉后只推「今天以后新上架」的，不回补老片

### 推送记录

每条离线任务的提交状态。失败的会写明原因（磁力失效、115 空间不足、任务被拒等）。

## 数据与备份

所有运行时数据都在 `data/` 目录下的一个 SQLite 文件里：

```
data/app.db
```

**备份**：

```bash
tar czf jiaofu115-backup.tar.gz data/
```

**恢复**：把 `data/` 放回去，重启容器。

**升级**：

```bash
docker compose pull && docker compose up -d
```

数据库表结构会在启动时自动建，`data/` 不用重建。

## 自己构建镜像

不用等 CI，本地也能构建：

```bash
git clone https://github.com/Loading543/jiaofu115.git
cd jiaofu115
docker build -t jiaofu115 .
docker run -d --name jiaofu115 --restart unless-stopped \
  -p 8123:8123 -v $(pwd)/data:/data jiaofu115
```

仓库里带了 GitHub Actions 配置（`.github/workflows/docker.yml`），推到 `main` 会自动构建并推送到 `ghcr.io`，打 `v*` tag 会额外打版本标签。

## 常见问题

**Q：页面能打开，但列表一直空**

先看「站点登录」页的状态是不是已登录。没登录的话程序会跳过抓取（日志里只有一条提示，不会刷屏）。

**Q：115 提示未登录**

115 的 Cookie 有有效期，重新扫码即可。如果频繁掉线，可能是 115 风控，换个网络环境或隔一会儿再试。

**Q：推送一直失败**

看「推送记录」里的具体原因。常见的是磁力失效（站点那边的种子挂了）或 115 空间不足。

**Q：怎么完全卸载**

```bash
docker compose down
rm -rf data/
```

## 安全提醒

**这个程序没有登录密码。** 谁能访问 `8123` 端口，谁就能操作你的 115 网盘（删文件、离线下载）。

- **只在内网用，不要把端口映射到公网**
- 必须外网访问的话，前面挂 Nginx / Traefik，加一层 HTTP Basic Auth
- `data/app.db` 里存着站点密码和 115 Cookie，**别把这个目录分享出去**
- `.gitignore` 已经排掉了 `data/` 和 `.env`，但自己提交前再看一眼
